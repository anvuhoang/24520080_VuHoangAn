## Lessons Learned

1. **Two writers in one folder produce documents that do not match the code.** The earlier `docs/` version said that `MessageForm` has character counters (it has none), that the CORS call has `optionsSuccessStatus: 200` (it does not), quoted a masking line `key.toLowerCase().includes('password')` that is not in the code (the code uses a set of secret keys), said the hook ignores `err.name === 'AbortError'` (the code deliberately does not: audit #01) and quoted a runtime error that nobody had reproduced. All of it read as plausible. The cure is the rule of Lab 3: write every claim from a run or from the code, and one writer per folder.
2. **The deck's reference code is not the specification.** Of the four contracts that were run, none is safe to copy: slide 22 nests two `<main>` and ends in a dead end, slide 25 never passes the value to its `<input>`, slide 26 shows another channel's messages as "not loading", and slide 27 lets the client choose the id and stores anything. On top of that three slides use three different addresses for the same API (audit #03 to #07).
3. **A wrong assumption is cheaper to find with a test than with a review.** I wrote that slide 27 lets the client forge the id *and* the time; the test of it failed, and showed that the time comes after the spread, so only the id is forged. The audit now says what is true.
4. **The same mistake comes back.** The name-based `AbortError` check is Lab 3 audit #02 again. Having a test that names it (an `AbortError` that this code did not cause) caught it before the first commit, in two files.
5. **Breaking your own code shows holes in the tests.** The suite looked complete, yet it did not notice the loss of the style of the open link in three components, because it only checked the attribute that NavLink adds by itself. Two other survivors were not holes: the code protects itself twice there. Knowing which is which needs the run.
6. **jsdom has no layout, so a layout bug looks like a wrong number.** The first Chrome run printed `alerts 2` for an empty submit and I read it as "two fields were empty at that moment". It was a lost click: the error line of the field that was just left moved the button away from the pointer (audit #11). Compare every real-browser number with what the unit test says; when they differ, one of them is lying.
7. **Lazy loading is global state.** `React.lazy` remembers its module for the whole test file, so a test that expects the skeleton depends on the order of the tests. Test the skeleton on its own and with a lazy view that the test controls.
