## Lessons Learned

1. **A claim in your own notes needs a check behind it, like any other claim.** My log for P2 said that every sort key gives a different order. It was never checked, and it was wrong: three of the four keys gave `te, ces, roy, agg`, so a broken sort would have gone unnoticed. The P4 run printed the four orders next to each other and showed it; the data was changed and a test now asserts four different orders (Audit #06). Write the note from the output, not from the intention.
2. **Measure the thing itself, and measure the right thing.** I counted the lines of the notice from `scrollHeight`, which can never be smaller than the box, and "learned" that 375 px needs 4 lines; I checked alignment on the edges of the cells, which are always equal. Both gave confident, wrong answers. The text's own height (a `Range`) and the edge of the digits gave the real ones (Audit #03 and #05). A number is only as good as what it measures.
3. **The CSS cascade is invisible to jsdom.** Three of the real defects (numbers left-aligned by a stronger selector, a header word spilling into its neighbour, a notice one line too short) exist only in a real layout. They were found by running the production CSS in headless Chrome at many widths, including the awkward ones just either side of a breakpoint (639/640, 359/360, 479/480). Unit tests cannot replace that, and a browser run cannot replace unit tests.
4. **The deck's reference code is not the spec.** Following slide 30's hook literally paints the old target's time for a frame, slide 11's `disabled` button drops the focus, and slides 17 and 19 make a number box impossible to clear (Audit #07, #10, #11). Each was found by running the reference and looking at what it does, and the replacements are covered by tests.
5. **A test that cannot fail proves nothing; try to break your own code.** Breaking the source 32 ways showed which tests bite (31 of 32 changes were caught) and exactly where they do not: an equivalent `.sort(` that is covered by `grep`, a `key={index}` that React does not warn about, and an abort guard whose only effect is invisible after unmount. Knowing the three holes is worth more than a green run.
6. **Lighthouse 100 does not mean it is finished.** The page scores 100 for accessibility on mobile and desktop and still has a notice that drops one of two simultaneous results, a hook that ignores a new list, columns off screen with no cue and an empty band of space (Audit #08, #09, #12, #13). They were found by using the page with real events, reading the numbers, and writing tests; they are kept as open entries (two as `it.fails`) instead of being hidden.
