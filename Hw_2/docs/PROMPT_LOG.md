## Lessons Learned

1. **Read the slide's cross-references, not only its bullet list.** Slide 27 says to combine the piano with *Lab 2 HW 2's FIFO AudioTaskQueue*. My first plan built a new, simpler queue; checking the `lab-2` branch showed that the queue already existed and was tested, so the replay now runs on it (a task per note, `maxConcurrency` 1) and its 22 tests pass unchanged in this project. Re-using your own earlier work is what the slide asks for, and it only turned up because the reference was followed.
2. **A measurement can be wrong in the same way a program can.** I got the render count wrong twice before getting it right: a `<Profiler>` re-renders itself and showed 5 renders for a key that rendered 0 times, and in tests React's batching inside one `act()` hid renders and gave an empty result. Count the thing itself (the key's own render function), advance a fake clock in small steps, and check what a tool measures before trusting it.
3. **Lighthouse 100 does not mean it works for everyone.** The page scored 100 on mobile and desktop, yet focus is lost when Record disables itself, the keyboard has 88 tab stops, a key whose voice was taken over still looks pressed, and Stop silences keys the user holds (Audit #01–#04). Those showed up by using the app with real events, reading the accessibility tree and writing tests.
