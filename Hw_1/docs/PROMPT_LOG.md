## Lessons Learned

1. **A comment is a claim.** I wrote that `showModal()` throws on an open dialog, built a test stand-in on it, and a real Chrome run showed otherwise. The stand-in and the comment were corrected; the guard stays because it is harmless, but the reason was wrong.
2. **The deck's code is a sketch of the happy path.** The slide 30 handler works until the user presses Close or Back, and then it loses the filter and rewrites the history. Both only show in a browser with a real history.
3. **A passing audit tool is not the whole standard.** axe-core and Lighthouse report 0 problems here, and that covers what a machine can see. A screen reader, zoom and reduced motion were not tried (see the end of AI_FAILURE_AUDIT.md).
4. **The score is only as good as the file it measures.** SEO lost 8 points for a file that does not exist, because a single-page app answers every address with `index.html`.
5. **Mutation runs find holes and bad mutants.** One survivor was my own mutant being wrong. Reading each survivor before adding a test avoided a test that checks nothing.
6. **Check the output against the rules before running it.** Two violations of the project rules (span, a hard-coded colour) and a missing image fallback were found by reading, not by a failing test; the tests that now guard them were added afterwards.
