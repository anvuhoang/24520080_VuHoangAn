## Lessons Learned

1. **Lighthouse 100 is not accessibility.** The app scored 100 on mobile and desktop, yet five defects were still there: pad keys dead while the checkbox has focus, a meter that is read out 9 times per hit, the name "ASnare", a duplicate heading, and a meter that does not show what is played (Audit #01–#05). They were found by using the app with real key events and by reading the accessibility tree, and each now has a test.
2. **A piece can pass every check alone and still fail next to its neighbours.** `useDrumKeyboard` met all its requirements and all its unit tests, but ignoring every `<input>` only mattered once the shortcuts checkbox sat beside it (Audit #01). Test the assembled component, not only its parts.
3. **Silent failures need a tool.** An undefined CSS token is ignored without a warning and a layout that grows by 28 px looks fine in the code (Audit #06, #07). Measuring computed styles and comparing every `var(--…)` with the defined tokens caught both; also compare a number the code reports with the number it produces (Audit #04).
